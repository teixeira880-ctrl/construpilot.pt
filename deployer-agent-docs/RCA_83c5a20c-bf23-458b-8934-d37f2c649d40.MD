# RCA — ConstruPilot / cmrenov-ai : échec génération PDF des devis en PRODUCTION

## Résumé (TL;DR)
La cause n'est PAS une image de prod obsolète. L'image de production exécute BIEN la
dernière version de `backend/engines/pdf_docs.py` (le refactor `kind` est déployé).
L'endpoint PDF renvoie **HTTP 500** à cause d'une **`reportlab.platypus.doctemplate.LayoutError`** :
une ligne du tableau des lignes de devis est **plus haute (768 pt) que la hauteur utile
de la page A4** et ReportLab ne peut pas la découper → l'export échoue.
C'est un **bug de code (source)**, à corriger par E1. Un redéploiement à l'identique
NE corrige PAS le problème (même code = même image = même erreur).

## Hypothèse principale de l'utilisateur : RÉFUTÉE
- Le déploiement le plus récent `83c5a20c-bf23-458b-8934-d37f2c649d40` (type=redeploy)
  est **success**, terminé 2026-09-27T20:14:52Z, actif et servant le trafic.
- Vérifié en sandbox (source réel de ce run, extrait de l'image déployée) :
  - `pdf_docs.py` gère la nouvelle structure `kind` : `has_structure = any(b.get("kind") in SPECIAL ...)`
    (l.545) et branches `section`/`subsection`/`text`/`pagebreak`/`line` (l.551-621).
  - La stack trace de prod pointe vers `pdf_docs.py` **ligne 787** (`pdf.build(...)` dans
    `build_document_pdf`) — c'est le code refactoré, pas l'ancien.
- Donc : aucune `KeyError`/`AttributeError` sur les blocs `kind`. L'image de prod == code actuel.

## Cause racine (prouvée par les logs de prod)
Extrait des logs backend du run actif (Loki) :
```
reportlab.platypus.doctemplate.LayoutError: Flowable <Table@0x... 152 rows x 7 cols(tallest row 768)> with cell(0,0) containing
    raise LayoutError(ident)
    pdf.build(story, onFirstPage=_on_page, onLaterPages=_on_page)
  File "/app/backend/engines/pdf_docs.py", line 787, in build_document_pdf
  File "/app/backend/routes/documents.py", line 1678, in document_pdf
INFO:  ... "GET /api/documents/doc_3a5bf7fe66b3/pdf HTTP/1.1" 500 Internal Server Error
```
- Le tableau des lignes possède une **ligne dont la hauteur (768 pt) dépasse la hauteur
  utile d'une page A4**.
  - A4 = 842 pt ; marges du `SimpleDocTemplate` (l.712) : topMargin ≈ 16 mm (~45 pt),
    bottomMargin = 26 mm (~74 pt) → hauteur utile ≈ **~723 pt < 768 pt**.
- Le helper `_table()` (`engines/pdf_takeoff.py` l.81-90) construit un `Table(...)` simple
  avec seulement `repeatRows=1` — **aucune** option de découpe intra-ligne
  (`splitByRow`/`splitInRow`, pas de `LongTable`). Par défaut ReportLab découpe ENTRE les
  lignes mais **ne peut pas découper une ligne unique plus haute que le cadre** → `LayoutError`.
- La cellule fautive `cell(0,0)` correspond à la colonne « désignation » construite par
  `_desig_cell()` (`pdf_docs.py` l.522-531) : elle empile `désignation` + `description`
  détaillée (`<br/>`). Une **description longue** produit un `Paragraph` très haut → ligne 768 pt.

## Pourquoi « TOUS les devis » échouent en prod alors que le preview « marche »
- Les 3 devis testés en preview (`doc_portaltest_q1`, `doc_a2c9fc1d714c`,
  `doc_a2e582966fadc8e63bdc164f`) sont **courts** : leurs lignes tiennent dans la page → 200 OK.
- Les devis réels de prod (ex. `doc_3a5bf7fe66b3`) contiennent des **descriptions longues**
  générant une ligne trop haute → 500. C'est **dépendant des données**, pas de la version
  d'image. Le même code produirait la même erreur en preview sur ces mêmes documents.

## Réponses aux 3 questions posées
1. **Exception exacte** : `reportlab.platypus.doctemplate.LayoutError` (voir extrait ci-dessus).
   Pas un timeout, pas une KeyError sur `kind`.
2. **Build/déploiement** : terminé et réussi (run `83c5a20c`, success @20:14:52Z). Le backend
   de prod exécute bien la dernière version de `pdf_docs.py` (confirmé en sandbox).
3. **Code HTTP renvoyé** : **500 Internal Server Error** (répété sur `.../pdf`). L'appel non
   authentifié renvoie 401 « Non authentifié » — comportement normal de l'auth, pas la panne.

## Correctif recommandé (CODE — E1, requiert un redéploiement APRÈS le fix)
Empêcher qu'une ligne de tableau dépasse la hauteur de page. Options (par ordre de préférence) :
1. Activer la découpe intra-ligne de ReportLab dans `_table()` :
   utiliser `LongTable` et/ou passer `splitByRow=1, splitInRow=1` (ReportLab ≥ 3.5.34) afin
   qu'une cellule haute puisse se répartir sur plusieurs pages.
2. Et/ou borner la hauteur de `_desig_cell` : tronquer / segmenter les descriptions très
   longues, ou émettre la description longue comme flowable(s) séparé(s) découpable(s) plutôt
   que dans une seule cellule de tableau.
3. Défensif : encapsuler `pdf.build(...)` (l.787) pour renvoyer une erreur 422 explicite au
   lieu d'un 500 opaque quand un contenu ne tient pas.

Reproduction conseillée en sandbox : générer le PDF de `doc_3a5bf7fe66b3` (ou tout devis à
description longue) après application du correctif, vérifier un PDF valide et l'absence de
`LayoutError`.

## Ce qu'il NE faut PAS faire
- **Ne pas redéployer à l'identique.** Le code source est inchangé → l'image reconstruite
  serait identique → même `LayoutError`. Aucun effet correctif, uniquement du coût/temps.
- Redéployer n'a de sens qu'**après** le correctif code d'E1.
