# RCA — ConstruPilot (cmrenov-ai) — Assistant blocked & Plan analysis returns 0 structure

## Scope
Production deployment `cmrenov-ai` (construpilot.fr), active run `08b1c1d5-c16c-41c7-b2c2-805bdb60d30f`, tier_2, cloudflare frontend. Debug-only; nothing was changed.

## Verdict (both symptoms = ONE root cause)
Every LLM call in production is failing with a **budget-exceeded error on the Emergent LLM proxy key**, not a rate limit, not an auth failure, and not the user's own OpenAI key.

Verbatim from prod backend logs (run active pods, 2026-10-08 05:xx UTC):
```
engines.plan_structure - WARNING - detect_structure AI failed: Failed to generate chat completion:
litellm.RateLimitError: RateLimitError: OpenAIException - Budget has been exceeded!
Key=d9tggf1tfj6s73bci6v0 (sk-...u9QA) Current cost: 93.87009534946645, Max budget: 93.3737606252812
```
```
routes.plans_render - ERROR - _gemini_render_3d LLM error: ChatError Failed to generate multimodal completion:
litellm.RateLimitError: ... Budget has been exceeded! Key=d9tggf1tfj6s73bci6v0 ... Current cost: 93.87 Max budget: 93.37
```

Key facts proving this is the Emergent proxy budget, not a rate limit or the user OpenAI key:
- Error type is `litellm.RateLimitError` but the message body is **"Budget has been exceeded!"** with `Current cost 93.87 > Max budget 93.37` — this is the litellm **virtual-key budget cap**, i.e. credits/budget exhausted, NOT true per-minute rate limiting and NOT an OpenAI `insufficient_quota`/billing error.
- All models route through the SAME proxy (`provider = openai`, litellm) against the SAME virtual key `d9tggf1tfj6s73bci6v0`: logs show `LiteLLM completion() model= gpt-5.5`, `model= claude-sonnet-4-6`, `model= gemini/gemini-3-flash-preview`, `model= gemini-2.5-flash-image` — all emitted, all against that one budget key. (`gpt-5.5` is an Emergent-proxied model id, not a native OpenAI model — confirming traffic goes via the Emergent universal key.)
- The `openai._base_client - INFO - Retrying request` lines show the SDK retried (8x) then surfaced the budget error — retries don't help because the cap is account-level.

## Symptom 1 — Assistant blocked (/assistant)
- Flow: assistant primary (`gpt-5.5`) → budget exceeded → fallback (`claude-sonnet-4-6`) attempted → **also** budget exceeded (same proxy/key). Both legs were actually tried in the logs (`LiteLLM completion() model= claude-sonnet-4-6` present), so the fallback IS engaging — it just shares the same exhausted budget, so it is futile.
- `engines/assistant_fallback.py::friendly_error()` matches the "budget"/"exceeded" markers in that exception and returns the French "limite d'utilisation … réessayer dans quelques minutes" string. That is exactly what the user sees. Behaving as coded.
- `assistant_runtime {key:"openai_degraded"}`: the `assistant_runtime` collection **does not exist** in prod DB (`cmrenov-ai-test_database`). So there is NO stuck/active degraded flag — not a factor.

## Symptom 2 — Plan analysis returns 0 structure (/plan)
- `engines.plan_structure.detect_structure` makes the vision call via `gemini/gemini-3-flash-preview` through the same Emergent proxy and gets the identical **"Budget has been exceeded!"** error (logged repeatedly at 05:17/05:23/05:27). The code logs it as a WARNING and continues, yielding **0 walls/columns/beams/slabs**.
- Rooms = 6 comes from the non-AI vectorial PyMuPDF pass, which still works — that is why rooms are detected but structure is empty, and Estimation/Aciers are 0.
- No silent code bug: the vision call genuinely errored (budget), it did not "return empty".

## Secrets state (active run)
- `EMERGENT_LLM_KEY` — present, not empty. `OPENAI_API_KEY` — present, not empty. `GEMINI_API_KEY` / `GOOGLE_GEMINI_API_KEY` — present, not empty.
- Nothing is missing or blank. The problem is NOT a missing/stale secret — it is the **spend budget attached to the Emergent LLM key (`EMERGENT_LLM_KEY`, virtual key `d9tggf1tfj6s73bci6v0`) being used up** (93.87 of 93.37 budget).

## Error classification requested
- Failing call: all LLM/vision calls via the Emergent litellm proxy (assistant gpt-5.5 + claude fallback; plan `gemini-3-flash-preview`; also 3D render `_gemini_render_3d`).
- Error class: **BUDGET / CREDITS EXHAUSTED** (surfaced as `litellm.RateLimitError` → "Budget has been exceeded"). NOT rate-limit, NOT auth, NOT the user's own OpenAI billing/quota.
- Key at fault: **EMERGENT_LLM_KEY** (the Emergent universal LLM proxy budget). The user's own `OPENAI_API_KEY` is not implicated — traffic is not hitting native OpenAI.
- Prod secret/budget problem vs code problem: **budget/credit problem**, not a code problem.

## Fix
1. USER: Top up / increase the Emergent LLM credit budget for `EMERGENT_LLM_KEY`. Current cost (93.87) exceeded the key's max budget (93.37). Once budget is restored, both the assistant and plan-structure/vision calls recover with no code change and no redeploy.
2. (Optional, not the cause) Fallback is working but shares the same exhausted budget. If desired for resilience, routing a provider to native keys (`OPENAI_API_KEY` for OpenAI, native Gemini key with the gemini-native toggle ON) would decouple that provider from the Emergent proxy budget. This is an enhancement, not required to fix the outage.

## What was verified vs inferred
- Verified from prod: the budget-exceeded errors on assistant (gpt-5.5 + claude) and plan (gemini-3-flash) calls; secret presence; absence of `assistant_runtime` degraded record.
- Inferred: that rooms=6 comes from the non-AI vectorial pass (consistent with structure=0 under LLM failure); not separately reproduced.
